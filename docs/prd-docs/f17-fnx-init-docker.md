# F17: fnx init docker — Dockerfile Generation

**Status:** 📋 Planned  
**PRD Section:** Developer experience, containerization  
**Depends on:** F17 (fnx init)

**References:**

- [Create a function app in a local container](https://learn.microsoft.com/azure/azure-functions/functions-how-to-custom-container?tabs=core-tools%2Cacr%2Cazure-cli2%2Cazure-cli&pivots=azure-functions)
- [Create a function app in a local Linux container](https://learn.microsoft.com/azure/azure-functions/functions-create-container-registry)
- [Azure Functions base images](https://mcr.microsoft.com/catalog?search=functions)

## Problem

After scaffolding a function app with `fnx init`, developers who want to containerize their app must manually create a Dockerfile. There's no guided experience for generating a production-ready Dockerfile tailored to the function app's runtime and configuration.

## Scope

### In Scope

- `fnx init docker` command that generates a Dockerfile for an existing function app
- Supports path argument: `fnx init docker ./my-func-app` or `--path` flag
- Auto-detects runtime from `app-config.yaml` or `host.json`
- Generates runtime-specific Dockerfile (Python, Node.js, .NET, Java, PowerShell)
- Uses official Azure Functions base images (`mcr.microsoft.com/azure-functions/...`)
- Optional `.dockerignore` generation with `--with-ignore`
- Supports multi-stage builds for compiled languages (.NET, Java)
- Optional `--base-image` flag to override default base image
- Clear error messages when run outside a function app directory

### Out of Scope (Future Work)

| Scenario | Why Out of Scope | Future Feature |
| -------- | ---------------- | -------------- |
| **Docker Compose** | Multi-container orchestration is complex | `fnx init docker --compose` |
| **Kubernetes manifests** | K8s deployment is separate concern | `fnx init k8s` or `fnx init helm` |
| **Custom base images** | Security/compliance varies by org | `--base-image` flag (partial) |
| **Build and push** | Requires registry auth, CI/CD scope | `fnx docker build`, `fnx docker push` |
| **Dev containers** | VS Code devcontainer is separate | `fnx init devcontainer` |

## Design

### CLI Signature

```bash
# Generate Dockerfile in current function app directory
fnx init docker

# Specify function app path
fnx init docker ./my-func-app
fnx init docker --path ./my-func-app

# Specify output location
fnx init docker --output ./docker/Dockerfile

# Override base image
fnx init docker --base-image mcr.microsoft.com/azure-functions/python:4-python3.11-slim

# Include .dockerignore
fnx init docker --with-ignore

# Non-interactive mode (all defaults)
fnx init docker --yes
```

### Flags

| Flag | Short | Description | Default |
| ---- | ----- | ----------- | ------- |
| `[path]` | | Positional arg: path to function app directory | `.` (current dir) |
| `--path` | `-p` | Path to function app directory | `.` (current dir) |
| `--output` | `-o` | Output path for Dockerfile | `<path>/Dockerfile` |
| `--base-image` | | Override base image | (auto from runtime) |
| `--with-ignore` | | Generate `.dockerignore` | false |
| `--yes` | `-y` | Skip confirmation prompts | false |
| `--verbose` | `-v` | Show detailed output | false |

### Runtime Detection

The command detects the runtime from the following sources (in priority order):

1. `app-config.yaml` → `runtime.name` and `runtime.version`
2. `host.json` → infer from `extensionBundle` or worker runtime
3. Project files → `requirements.txt` (Python), `package.json` (Node), `*.csproj` (.NET), `pom.xml` (Java)

### Base Image Selection

| Runtime | Base Image |
| ------- | ---------- |
| Python 3.11 | `mcr.microsoft.com/azure-functions/python:4-python3.11` |
| Python 3.12 | `mcr.microsoft.com/azure-functions/python:4-python3.12` |
| Node.js 20 | `mcr.microsoft.com/azure-functions/node:4-node20` |
| Node.js 22 | `mcr.microsoft.com/azure-functions/node:4-node22` |
| .NET 8 | `mcr.microsoft.com/azure-functions/dotnet-isolated:4-dotnet-isolated8.0` |
| Java 17 | `mcr.microsoft.com/azure-functions/java:4-java17` |
| Java 21 | `mcr.microsoft.com/azure-functions/java:4-java21` |
| PowerShell 7 | `mcr.microsoft.com/azure-functions/powershell:4-powershell7.4` |

Slim variants (e.g., `-slim`) are used when available for smaller image size.

### Generated Dockerfile Examples

#### Python

```dockerfile
# Azure Functions Python Dockerfile
# Generated by fnx init docker

FROM mcr.microsoft.com/azure-functions/python:4-python3.11

ENV AzureWebJobsScriptRoot=/home/site/wwwroot \
    AzureFunctionsJobHost__Logging__Console__IsEnabled=true

COPY requirements.txt /
RUN pip install -r /requirements.txt

COPY . /home/site/wwwroot
```

#### Node.js (TypeScript)

```dockerfile
# Azure Functions Node.js Dockerfile
# Generated by fnx init docker

FROM mcr.microsoft.com/azure-functions/node:4-node20

ENV AzureWebJobsScriptRoot=/home/site/wwwroot \
    AzureFunctionsJobHost__Logging__Console__IsEnabled=true

COPY package*.json /home/site/wwwroot/
WORKDIR /home/site/wwwroot
RUN npm ci --only=production

COPY . /home/site/wwwroot
RUN npm run build
```

#### .NET (Multi-stage)

```dockerfile
# Azure Functions .NET Isolated Dockerfile
# Generated by fnx init docker

# Build stage
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
COPY *.csproj .
RUN dotnet restore
COPY . .
RUN dotnet publish -c Release -o /app/publish

# Runtime stage
FROM mcr.microsoft.com/azure-functions/dotnet-isolated:4-dotnet-isolated8.0
ENV AzureWebJobsScriptRoot=/home/site/wwwroot \
    AzureFunctionsJobHost__Logging__Console__IsEnabled=true

COPY --from=build /app/publish /home/site/wwwroot
```

#### Java (Multi-stage with Maven)

```dockerfile
# Azure Functions Java Dockerfile
# Generated by fnx init docker

# Build stage
FROM mcr.microsoft.com/openjdk/jdk:21-ubuntu AS build
WORKDIR /src
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

# Runtime stage
FROM mcr.microsoft.com/azure-functions/java:4-java21
ENV AzureWebJobsScriptRoot=/home/site/wwwroot \
    AzureFunctionsJobHost__Logging__Console__IsEnabled=true

COPY --from=build /src/target/azure-functions/*/ /home/site/wwwroot
```

### Error Handling

| Stage | Error | Message |
| ----- | ----- | ------- |
| Directory check | Not a function app | `✗ Not a function app directory at '<path>'. Run 'fnx init' first.` |
| Runtime detection | Cannot detect runtime | `✗ Cannot detect runtime. Ensure app-config.yaml or host.json exists.` |
| File write | Dockerfile exists | `✗ Dockerfile already exists. Use --force to overwrite.` |

## Success Criteria

- [ ] `fnx init docker` generates a working Dockerfile for all 5 runtimes
- [ ] Generated Dockerfile builds successfully with `docker build`
- [ ] Generated container runs and responds to HTTP requests
- [ ] Multi-stage builds work for .NET and Java
- [ ] `--with-ignore` generates appropriate `.dockerignore`
- [ ] Runtime auto-detection works from `app-config.yaml`
