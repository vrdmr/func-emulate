# F17: fnx init cd ado — Azure DevOps Pipelines CI/CD

**Status:** 📋 Planned  
**PRD Section:** Developer experience, continuous deployment  
**Depends on:** F17 (fnx init)

## Problem

After scaffolding a function app with `fnx init`, developers who want to set up continuous deployment using Azure DevOps must manually create pipeline YAML files. There's no guided experience for generating a production-ready `azure-pipelines.yml` tailored to the function app's runtime and deployment target.

## Scope

### In Scope

- `fnx init cd ado` command that generates Azure Pipelines YAML for an existing function app
- Supports path argument: `fnx init cd ado ./my-func-app` or `--path` flag
- Auto-detects runtime from `app-config.yaml` or project files
- Supports two deployment modes:
  - **Zip deploy** (default) — Build artifacts and deploy via [`AzureFunctionApp@2`](https://learn.microsoft.com/azure/devops/pipelines/tasks/reference/azure-function-app-v2) task
  - **Container deploy** — Build Docker image and deploy to Azure Container Apps or Functions
- Generates `azure-pipelines.yml` with:
  - Build step appropriate for runtime
  - Test step (if test script exists)
  - Deploy step with Azure service connection
- Includes guidance for setting up Azure service connection in Azure DevOps
- **Auto-invokes `fnx init docker`** when container mode selected and no Dockerfile exists
- Clear error messages when run outside a function app directory

### Out of Scope (Future Work)

| Scenario | Why Out of Scope | Future Feature |
| -------- | ---------------- | -------------- |
| **Multi-stage pipelines** | Requires environment strategy | `--environments staging,prod` |
| **Approval gates** | Requires ADO environment setup | Manual YAML edit |
| **Self-hosted agents** | Org-specific configuration | `--pool self-hosted` |
| **Template references** | Org-wide template standards | Template library |
| **Variable groups** | Requires ADO library setup | `--variable-group` flag |
| **PR validation pipelines** | Separate from deploy pipeline | `fnx init cd ado --pr` |

## Design

### CLI Signature

```bash
# Generate Azure Pipelines YAML (zip deploy)
fnx init cd ado

# Specify function app path
fnx init cd ado ./my-func-app
fnx init cd ado --path ./my-func-app

# Container deployment mode
fnx init cd ado --container

# Specify Azure resource names
fnx init cd ado --app-name my-func-app --resource-group my-rg

# Specify service connection name
fnx init cd ado --service-connection "Azure-Prod"

# Specify branch trigger
fnx init cd ado --branch main

# Non-interactive mode
fnx init cd ado --yes
```

### Flags

| Flag | Short | Description | Default |
| ---- | ----- | ----------- | ------- |
| `[path]` | | Positional arg: path to function app directory | `.` (current dir) |
| `--path` | `-p` | Path to function app directory | `.` (current dir) |
| `--container` | | Use container deployment instead of zip deploy | false |
| `--app-name` | | Azure Function App name | (prompt) |
| `--resource-group` | `-g` | Azure resource group | (prompt) |
| `--service-connection` | `-s` | Azure DevOps service connection name | (prompt) |
| `--branch` | `-b` | Branch to trigger deployment | `main` |
| `--output` | `-o` | Output path for pipeline file | `azure-pipelines.yml` |
| `--yes` | `-y` | Skip confirmation prompts | false |
| `--verbose` | `-v` | Show detailed output | false |

### Runtime Detection

Same as `fnx init docker` and `fnx init cd github` — detects runtime from:

1. `app-config.yaml` → `runtime.name` and `runtime.version`
2. `host.json` → infer from `extensionBundle` or worker runtime
3. Project files → `requirements.txt`, `package.json`, `*.csproj`, `pom.xml`

### Generated Pipeline Examples

#### Python (Zip Deploy)

```yaml
# Azure Pipelines YAML for Azure Functions
# Generated by fnx init cd ado

trigger:
  branches:
    include:
      - main

pool:
  vmImage: 'ubuntu-latest'

variables:
  azureSubscription: 'Azure-Prod'
  functionAppName: 'my-func-app'
  resourceGroupName: 'my-resource-group'

stages:
  - stage: Build
    displayName: 'Build'
    jobs:
      - job: Build
        displayName: 'Build Function App'
        steps:
          - task: UsePythonVersion@0
            inputs:
              versionSpec: '3.11'
            displayName: 'Use Python 3.11'

          - script: |
              python -m pip install --upgrade pip
              pip install -r requirements.txt
            displayName: 'Install dependencies'

          - script: |
              pip install pytest
              pytest tests/ --tb=short --junitxml=test-results.xml
            displayName: 'Run tests'
            continueOnError: true

          - task: PublishTestResults@2
            inputs:
              testResultsFiles: 'test-results.xml'
              testRunTitle: 'Python Tests'
            condition: always()

          - task: ArchiveFiles@2
            inputs:
              rootFolderOrFile: '$(System.DefaultWorkingDirectory)'
              includeRootFolder: false
              archiveType: 'zip'
              archiveFile: '$(Build.ArtifactStagingDirectory)/$(Build.BuildId).zip'
              replaceExistingArchive: true
            displayName: 'Archive files'

          - publish: '$(Build.ArtifactStagingDirectory)/$(Build.BuildId).zip'
            artifact: drop
            displayName: 'Publish artifact'

  - stage: Deploy
    displayName: 'Deploy'
    dependsOn: Build
    condition: succeeded()
    jobs:
      - deployment: Deploy
        displayName: 'Deploy to Azure Functions'
        environment: 'production'
        strategy:
          runOnce:
            deploy:
              steps:
                - task: AzureFunctionApp@2
                  inputs:
                    azureSubscription: '$(azureSubscription)'
                    appType: 'functionAppLinux'
                    appName: '$(functionAppName)'
                    package: '$(Pipeline.Workspace)/drop/$(Build.BuildId).zip'
                    runtimeStack: 'PYTHON|3.11'
                  displayName: 'Deploy to Azure Functions'
```

#### Container Deploy (Any Runtime)

When `--container` flag is used:

```yaml
# Azure Pipelines YAML for Azure Functions (Container)
# Generated by fnx init cd ado --container

trigger:
  branches:
    include:
      - main

pool:
  vmImage: 'ubuntu-latest'

variables:
  azureSubscription: 'Azure-Prod'
  functionAppName: 'my-func-app'
  resourceGroupName: 'my-resource-group'
  containerRegistry: 'myregistry.azurecr.io'
  imageName: 'my-func-app'
  imageTag: '$(Build.BuildId)'

stages:
  - stage: Build
    displayName: 'Build'
    jobs:
      - job: Build
        displayName: 'Build Container Image'
        steps:
          - task: Docker@2
            inputs:
              containerRegistry: '$(containerRegistry)'
              repository: '$(imageName)'
              command: 'buildAndPush'
              Dockerfile: '**/Dockerfile'
              tags: |
                $(imageTag)
                latest
            displayName: 'Build and push image'

  - stage: Deploy
    displayName: 'Deploy'
    dependsOn: Build
    condition: succeeded()
    jobs:
      - deployment: Deploy
        displayName: 'Deploy to Azure Functions'
        environment: 'production'
        strategy:
          runOnce:
            deploy:
              steps:
                - task: AzureCLI@2
                  inputs:
                    azureSubscription: '$(azureSubscription)'
                    scriptType: 'bash'
                    scriptLocation: 'inlineScript'
                    inlineScript: |
                      az functionapp config container set \
                        --name $(functionAppName) \
                        --resource-group $(resourceGroupName) \
                        --image $(containerRegistry)/$(imageName):$(imageTag)
                  displayName: 'Deploy container to Azure Functions'
```

### Service Connection Setup Guidance

The CLI directs users to the official documentation for setting up Azure service connections:

**Documentation:** https://learn.microsoft.com/azure/devops/pipelines/library/connect-to-azure?view=azure-devops

The interactive flow displays:

```text
To set up an Azure DevOps Service Connection:

  1. Go to Project Settings → Service connections
  2. Click "New service connection" → "Azure Resource Manager"
  3. Follow the setup wizard (Workload Identity Federation recommended)

  Documentation: https://learn.microsoft.com/azure/devops/pipelines/library/connect-to-azure
```

### Error Handling

| Stage | Error | Message |
| ----- | ----- | ------- |
| Directory check | Not a function app | `✗ Not a function app directory at '<path>'. Run 'fnx init' first.` |
| Runtime detection | Cannot detect runtime | `✗ Cannot detect runtime. Ensure app-config.yaml or project files exist.` |
| File write | Pipeline exists | `✗ Pipeline already exists at azure-pipelines.yml. Use --force to overwrite.` |

### Container Mode Behavior

When `--container` is specified and no Dockerfile exists, the command automatically invokes `fnx init docker`:

```text
? Deployment method: Container deploy

No Dockerfile found. Generating one...
  ✓ Created ./Dockerfile
  ✓ Created ./.dockerignore

Creating pipeline...
  ✓ Created azure-pipelines.yml
```

This seamless flow eliminates the need for users to run separate commands.
